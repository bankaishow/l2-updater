# Апдейтер клиента: план

Дата: 2026-10-22. Исполнитель: Gemini с 2026-10-23, до этого Kimi (отдельный пользователь Linux, свой репозиторий), проверка и безопасность: Claude.

## Что это для игрока

Одна программа `L2Updater.exe` для Windows:
1. При запуске показывает список клиентов (сейчас 2, можно 3 и больше): например «Interlude / Classic (Lucera)», «High Five (Mythras)». Игрок выбирает, где у него лежит папка игры.
2. Проверяет файлы выбранного клиента и докачивает только изменённые (патчи), с проверкой SHA256 каждого файла.
3. Кнопка «Играть» запускает игру. Ещё: новости и статус серверов с сайта, кнопки «Сайт», «Форум», «Кабинет», «Проверить все файлы».
4. Сам обновляет себя, когда выходит новая версия апдейтера.

## Конфигурация (без перекомпиляции)

Список клиентов и всё, что меняется, приходит **с сайта** в файле `manifest.json`. Пример ниже упрощённый и устаревший: точный формат только в `docs/format.md`.

```json
{
  "version": 3,
  "updater": { "version": "1.0.2", "url": "...", "sha256": "..." },
  "clients": [
    {
      "id": "mythras",
      "title": { "ru": "High Five", "en": "High Five" },
      "exe": "system/l2.exe", "args": "",
      "files_url": "https://.../mythras/files.json",
      "base_url": ["https://зеркало1/mythras/", "https://зеркало2/mythras/"],
      "servers": ["mythras_x1"]
    }
  ],
  "links": { "site": "...", "forum": "...", "cabinet": "..." }
}
```

- Новый клиент = новая запись в `clients`, апдейтер пересобирать не нужно.
- `files.json` клиента: путь, размер, SHA256 каждого файла, плюс список файлов, которые игрок может менять сам (настройки, макросы) — их апдейтер не перезаписывает.
- Рядом с exe маленький `updater.ini`: адрес сайта и последний выбранный клиент. Можно раздавать разные сборки апдейтера под разные домены (зеркала сайта, D-97).

## Безопасность (главное)

- `manifest.json` и каждый `files.json` **подписаны ключом ECDSA P-256**. Открытый ключ зашит в апдейтер, закрытый хранится только у владельца (не на сайте и не на сервере сайта). Даже если сайт взломают, подсунуть игрокам чужой файл нельзя: подпись не сойдётся.
- Скачанный файл кладётся во временную папку, проверяется SHA256, только потом заменяет старый. Пути из списка проверяются: никаких `..`, абсолютных путей, выхода за папку игры.
- Только `https://`. Без прав администратора Windows (если игра стоит в Program Files — подсказка перенести папку).
- Апдейтер не трогает ничего вне папки игры и своей папки, не собирает данные игрока, не встраивается в игру (это не защита клиента).
- Самообновление тоже по подписи.
- Подпись кода Windows (сертификат владельца): без неё SmartScreen и антивирусы показывают предупреждение.

## Сайт (делает Claude)

- Раздел админки «Апдейтер»: клиенты (название, папка, exe, зеркала), версия апдейтера.
- Команда для владельца на своём компьютере или машине разработки: `updater-build <клиент> <папка клиента>` — считает SHA256, собирает `files.json`, подписывает закрытым ключом. Результат загружается на хранилище файлов и сайт.
- Сайт отдаёт `manifest.json` и новости/статус для окна апдейтера (короткий JSON, кэш).

## Где лежат файлы патчей

Клиенты весят гигабайты, качать их через туннель Cloudflare с домашней виртуалки нельзя (канал и правила Cloudflare). Предлагаю **Cloudflare R2** (хранилище файлов: исходящий трафик бесплатный, ~0.015 $ за ГБ хранения в месяц) или любые зеркала по https; в `base_url` несколько адресов, апдейтер переключается при ошибке.

## Технологии (допущение, можно поменять)

C# .NET 8, WinForms, один файл exe (self-contained, ~60 МБ). Собирается на Linux (.NET SDK), без Windows. Подпись ECDSA P-256 + SHA-256: встроена в .NET, без сторонних библиотек. Код в отдельном публичном репозитории `l2-updater` (MIT).

## Этапы

1. Каркас: окно, выбор клиента, чтение и проверка подписи `manifest.json` (тестовый ключ), проверка файлов по `files.json`.
2. Скачивание с зеркал, докачка, замена файлов, «Играть».
3. Сайт: админка, `updater-build`, отдача manifest; живой тест на машине разработки с небольшим тестовым клиентом.
4. Самообновление, новости/статус, RU/EN, оформление.
5. Аудит безопасности (Claude), подпись кода, тест на чистой Windows (владелец), выпуск.
